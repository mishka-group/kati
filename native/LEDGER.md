# Drift ledger

Every Kati edit to a vendored native file. One row per fence label.
`test/kati/native_ledger_test.exs` fails the build if a fence exists that is not listed here, or a
row here has no matching fence — so this file cannot silently rot.

**Upstream status** is what lets a patch eventually be retired: once a defect is fixed upstream and
the baseline is refreshed, the fence goes and the row moves to *Retired*.

**A `K-nn` names one change, not one file.** Several fences share a number when they are the same
edit landing in several places — `K-32` is the eight fences of the AGP 9 / Kotlin 2 migration, and
`K-31` is the four of the dependency prune. Picking the next free number is therefore not the same
as picking the highest: **read the rows for a number before joining it.** `permission-status` was
appended to `K-32` and had nothing to do with the toolchain migration; the ledger test did not
catch it, because it checks that every fence is documented rather than that a number means one
thing. Nothing mechanical can check that. This paragraph is the check.
